## Como nasceu a lista
Cinco leitores (só leitura) mapearam o produto por área e gravaram itens concretos (problema, solução, arquivo, como verificar):

servidor/banco/operação (5º mapa). Os mapas ficam no scratchpad da sessão (`mapa1000/*.json`); os lotes de trabalho em `lotes/*.json`.

## Regras para todas as frentes (valem também as do plano 100)
- **Só os arquivos da sua frente** (tabela abaixo). Precisou de outro arquivo (ui.js, app.js, app.css, dev-falso…)? Não edite: anote no
  relatório final como pendência com o trecho exato sugerido.
- **Cada item com teste de comportamento** em `testes/plano1000-<frente>.teste.mjs` (node:test), que falharia no código antigo. Os testes
  existentes continuam verdes; teste antigo que fixava o comportamento ruim muda junto, com comentário «plano 1000: …».
- Item do lote que, olhando de perto, não é real, já está feito ou é ruim para o produto: **não faça** — liste como «descartado» com o
  motivo. Nunca invente número, nunca contrarie as decisões do plano 100.
- Itens `precisa_servidor` ficam nos lotes `-srv` (banco/funções); a tela os consome por detecção, com reserva honesta.
- Design: tokens do app.css (nada de número solto/hex), celular primeiro (360/390 sem rolagem horizontal, alvos de 44 px),
  `prefers-reduced-motion`, foco visível, textos em português claro, vocabulário por vertical (`vocab.js`).
- Teste visual só no dev-falso (`ORBITA_DEV_FALSO_PORT=<porta própria> node scripts/dev-falso.mjs`, `/app/?dev-falso=1#/rota`); nunca
  produção. Nada de commit, `bump-versao`, `?v=` ou `versao.json` (o integrador faz). `git diff --check` limpo.
- **Vários agentes editam ao mesmo tempo:** nunca `git stash`, `git checkout/restore` de arquivo, `git reset` (em 13/10 um stash
  apagou por ~20 s o trabalho de todas as frentes). Para comparar com o antigo: `git show HEAD:<arquivo> > <pasta temporária>`.
- Atenção a escapes: nunca gerar código com barras invertidas dentro de template string de script Node — use o Edit direto.
